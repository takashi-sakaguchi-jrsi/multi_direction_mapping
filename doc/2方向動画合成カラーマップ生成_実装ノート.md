## 3. 採用した処理

### 3.1 角度規約（仕様 §1.2, §4, §16）

カメラカーの初期方位（pitch=90°、roll=0/120/240）とプログラム Euler（`CameraState = [roll, yaw, pitch]`、`R_c2w = R_roll @ R_pitch @ R_yaw`）は定義が異なる。回転順を流用せず、光軸とカメラ「上」が Demo 生成と一致する組を表で持つ。

| カメラカー (pitch, roll) | プログラム (roll, yaw, pitch) [deg] | 識別 |
| --- | --- | --- |
| (90, 0) | (−90, 90, 90) | U 真上。旧 (0,0,90) と同一姿勢 |
| (90, 120) | (−90, 90, −30) | R 右下 |
| (90, 240) 内部 −120 | (90, −90, −30) | L 左下 |

- 120°/−120° は**光軸**であり接合線ではない。重なり中央（カット線）はカメラカー角 **60° / −60° / 180°**。担当帯はそれぞれ 120°（U: −60～60、R: 60～180、L: 180～300）。
- R のプログラム roll を −90 にしたのは、光軸周りの 180° 不定性を Demo のカメラ上に合わせるため。カメラ姿勢 +90° と画像回転 −90° が逆だと 180° ずれる。
- η は `atan2(y, x)+π/2`。カメラカー角との変換は `η_deg = (180 − car_deg) mod 360`。

### 3.2 仮想動画生成（仕様外の検証手段）

仕様は実動画前提だが、再現確認のため既存展開図から等距離魚眼（FOV 181°）で U/R/L を生成する。

- エントリ: `src/generate_two_direction_test_videos.py`
- 正本: `original_colormap/phi250tenkaizu.png`（φ250 mm）。基準線入りは `phi250tenkaizu_line.jpg`
- 生成モデル: `f = r_max / (FOV/2)` → **f=341.875 px**、cx=960、cy=540、歪み k=0。距離 overlay / Phase1 は焼き込まない
- 公称速度 **4.5 mm/frame**（5 mm/frame だと 10 mm OCR 刻みと同期してしまう）
- `--jitter`: dz / yaw / pitch に十数フレーム周期の中程度振動と 2～3 フレームの小さい振動を合成。yaw/pitch は基準まわり（積算ドリフトしない）。OCR 列は真の累積 z に 10 mm 遅れモデルを掛ける
- 振幅・周期は `PoseJitterConfig`（`src/validation/pose_jitter.py`）

```bash
python src/generate_two_direction_test_videos.py --fov 181 --runs U,R,L --frames 150 --z-start-mm 10 --z-step-mm 4.5 --jitter
```

全長動画は `--frames` を大きくし、管路 z 範囲−マージンでクリップする（`--z-end` はない）。フレームは `VideoWriter` へ逐次書き、全 HD を RAM に置かない。

現設定 `data/config/two_direction_config.json` は `phi250_baseline_{U,R,L}.mp4` と `phi250_baseline_metadata.json`（公称 4.5 mm/frame、既知 z）を指す。`run_C.video_path` が空なら 2 方向。

### 3.3 距離（仕様 §6）

- 実経路: Tesseract OCR。仮想第1段階: `z_source=known` で metadata の z / シミュレート OCR を代用し、Tesseract を呼ばない
- OCR モデル: 10 mm 単位。刻みラインを**超えた**フレームでのみカウントアップ（ジャストでは上がらない）
- カメラ z 系列は OCR 制約のもとでフレーム間 dz を積算。部分図の z 方向なだらか補正は推定 z をこの OCR 系列に合わせる PCHIP（端の立方外挿はしない）

### 3.4 フレーム範囲（最終プログラム前提の先行実装）

`[start_frame, end_frame)`（0 始まり、end は含まない）。`--max-frames` は start からの枚数上限。動画と既知 z / OCR を同じ区間で切る。CSV の `frame_num` と時刻は元動画の番号。

```bash
python src/main_two_direction_validation.py --mode A --start-frame 150 --end-frame 200
```

### 3.5 Mode A 姿勢推定（仕様 §5.1 からの採用差）

仕様 Mode A は x/y=0・roll 固定のうえ **z/yaw/pitch を推定**する。壁面正対の観測性から、実装は方向でパラメータを分け、**yaw（光軸まわり捩れ）は全 run で固定**する。

| Run | 固定 | 推定 | 残差 | 求心 |
| --- | --- | --- | --- | --- |
| U | x=y=0、roll=−90°、**yaw=90°** | dz、dpitch | フレーム (u,v)。**dz と dpitch を同一予測**して再投影 | pitch → 90° |
| R/L | x=y=0、roll=r0、**yaw=y0** | dz、dpitch | 円筒 3D `‖p0−p1‖` | pitch → p0（R は −30°） |

理由:

- U 初期 `(-90,90,90)` は旧 `(0,0,90)` と同一姿勢。プログラム pitch が周方向（車体 roll）、yaw と roll は pitch≈90° で**同じ光軸まわり捩れ**になる
- 捩れを Mode A の自由変数に入れると中心 ROI の x 流れに載り、pitch が相殺して積算する（§4.13）
- R のプログラム pitch は周方向、yaw は進行面チルト。(dz, dpitch) はほぼ無相関。(dz, dyaw) は結合する
- 接合ワープは展開図上の (Δz, Δθ) **平行移動**であり、垂直基準線の湾曲（光軸捩れ）は吸収できない
- 最小二乗の座標は **U=フレーム、R=円筒**。U を (z,θ) に移しても捩れは θ ではない

U の逆投影は `pixel_to_world_R_c2w`（`world_to_pixel` と同じ `R_c2w` 視線）。正面用 `pixel_to_world` は真横で画像 x が反転する。

特徴点（壁面正対）:

- レンズ中央付近の矩形 ROI（外周円 0.8 と 8×8 間引きは使わない）
- Lowe 比、逆走（画像 y が正の流れ）除外、方向角とベクトル長の IQR 外れ値除外

center prior と hard bounds（yaw 偏差 ±20°、pitch 偏差 ±25° など）は仕様どおり reference 中心。loss は soft_l1。

Mode C（6DoF + prior）は `estimate_motion_flexible` に残してある。

### 3.6 展開（仕様 §7）

- 格子への**逆投影**と帯サイズの `cv2.remap`（INTER_LINEAR）。HD 源への `scipy.map_coordinates` は使わない
- 1 フレームの帯は相対 z = `[0, max_dz * alpha]`（巨大 FOV の先まで取ると姿勢誤差が伸びる）
- 同一格子は後勝ち上書き。キャンバスはオリジナル `ColorMapGenerator.update_colormap` と同じく **右へ 2048 列単位で伸ばす**（全行程を先確保しない）
- 仮想再現では `match_source_pixels_per_mm` で元展開図の pix/mm に揃える

### 3.7 z / 接合補正（仕様 §8 からの採用差）

1. OCR 基準で z=0～z_max をなだらかに変形。z_max～画像右端は補正せず貼る（オリジナルと同様）
2. 接合面で ORB+NCC により (Δz, Δθ) を測り、**半分ずつ**相互補正。端はピンしない。120° 帯内は θ 線形ブレンド。相手の無い接合は変位 0。3 方向では各 run が両隣を境界条件にする（U: L と R、R: U と L、L: R と U）
3. 仕様にあった「初期方位から見たエッジ角中心への θ 変形」は、接合ワープを入れると二重になるため **オフ**（`seam_warp.apply_edge_theta=false`）
4. 担当帯の分割は重なり中央 **60/−60/180**（接合面）。最終展開図の周期切断は **θ=0（真上）**。接合ワープの `cv2.remap` は θ を周期パッドする（非周期だと旧切断 η=0＝180° が黒帯になる）。残った短い穴は接合後に周期方向で埋める
5. **180°（R/L）は η=0 の周期ラップ**。R の 180° 線は展開の先頭行付近、L は最終行付近。接合帯を θ 周期で切らないと L 側を見ず、両 180° 線が残る（§4.16）。既定の採用上限は `max_dz_mm=40`、`max_dtheta_deg=6`

仕様の「A を正解にしない Global RANSAC → 共同 z、θ は定数オフセット」は、仮想検証では上記 1–4 で代替している。

### 3.8 レンズ（仕様 §7.3 と仮想検証）

仕様の usable half FOV 71.97° は本番 fx と `outer_radius_ratio=0.8` から出る値。仮想検証では**本番校正 JSON を外し**、生成と同じ f/cx/cy・k=0 にする。生成と推定でレンズが違うと U の yaw が一方に偏る。

### 3.9 全長処理のメモリ

オリジナル `ColorMapGenerator` は RGB だけを進んだ分だけ右へ伸ばす。検証側が全行程の z を `pixels_per_mm≈2.55` で先確保し、毎フレーム 1080p 全体で ORB すると WSL が数百〜千フレームで落ちた。

採用:

- 蓄積キャンバスは種幅から 2048 列単位で伸長（`BestViewAccumulator._grow_to`）
- 解析・蓄積は動画をストリームし、既知 z なら OCR 用に全フレームを持たない
- ORB は中央 ROI の切り出しだけ（全画面マスクを作らない）
- z/θ リマップと接合 ORB は列チャンク。巨大 PNG は行単位 zlib
- 1 run の蓄積が終わったら `acc` を捨てて `gc.collect`

### 3.10 巨大 PNG の保存と表示

`cv2.imwrite` は幅 32767 超で使えないため自前書き。当初はフィルタ None + IDAT 1MiB で、オリジナル（libpng: Sub + 約 8KiB IDAT + zlib fastest）と構造が違い、先頭チャンクだけ描くビューアでは 0° 付近だけ見えた。

現行はオリジナルに合わせ **Sub フィルタ・zlib fastest・8KiB IDAT**。幅 16384 超では θ 実寸のまま z を間引いた `*_photoviewer.png` と、全体縮小の `*_preview.png` も出す。フォトビューアで先頭だけになる現象は、IDAT だけでなく **空き RAM 不足**でも同じ見え方になる（再起動後は全長 `final.png` も表示できた）。

## 4. 発生した課題と改修

時系列ではなく、あとから参照しやすい単位で書く。

### 4.1 カメラカー角とプログラム Euler の取り違え

初期にプログラム角をカメラカー roll に直接入れ、R の展開が壊れた。変換表（§3.1）に切り替え、R の光軸周りの 180° も Demo の「上」に合わせた。

### 4.2 接合角 120° の誤解

120°/−120° を継ぎ目だと思い込んだが、これは光軸である。カットは重なり中央 60/−60/180。U+R のみなら実継ぎ目は 60°。

### 4.3 スプライン開始点のフレア / PCHIP

z 補正の立方スプラインが先頭で大きく歪んだ。厳密増加の制御点、端勾配の平坦化、薄い列の削除、立方外挿禁止で回避。

### 4.4 部分図の途切れと「補正せず貼る」右端

補正後画像が推定 z_max で切れ、オリジナル右端の堆積物が消えた。オリジナル同様、z_max 以遠は補正前を貼る。古い出力画像を見ると途切れが残ることがある。

### 4.5 基準線のぼけと d_wall 最小

順投影や d_wall 最小の画素選択は、同一格子への複数寄与で線がぶれた。逆投影＋座標上書きに戻した。

### 4.6 帯が太すぎて移動量推定が崩れた

展開 FOV が大きいと、端の画素が姿勢誤差を増幅し特徴点推定が悪化した。帯を `[0, max_dz * alpha]` に制限。壁面正対用に ROI・逆走・IQR を入れ、8×8 間引きは外した。

### 4.7 U の (dz, dpitch) 線形結合

U で pitch を自由にすると進行面チルトと dz が区別できず、pitch が +2°/frame で 115° まで走った。U は pitch=90° 固定、dx は dyaw のみ。

### 4.8 逆投影と順投影の不一致（yaw が制限に当たる）

`pixel_to_world`（正面用レイ組み直し）と `world_to_pixel`（`R_c2w`）の往復が水平方向で約 200 px ずれた。差が yaw に載り hard bound（±20°）へ張り付いた。U は `pixel_to_world_R_c2w` に統一。

### 4.9 生成レンズと本番校正の不一致

仮想動画は無歪み等距離、推定側が本番 `fisheye_recalibrated_*.json` だと yaw が一方に偏る。仮想用 config で校正を外し f/cx/cy を生成に合わせた。

### 4.10 接合の z ずれと 2D ねじれ

OCR z だけでは中間の継ぎ目がずれ、重ねると微小なねじれも残った。接合面マッチの 1/2 相互ワープ（§3.7）を追加。端固定のスプラインは使わない。

### 4.11 U 残差の足し分けによる yaw 雪崩

「dy→dz、dx→dyaw」を **残差の加算分割**（垂直は旧 yaw の dz、水平は旧 z の dyaw）にすると、yaw が 0 から外れた瞬間に z 移動の横漏れがすべて dyaw に載り、正帰還で制限まで走る。150–200 フレームだけ切っても再現した。

改修: パラメータは従来どおり (dz, dyaw) のまま、**同一姿勢で再投影した (u,v) 残差**にする。ヤコビアンが yaw=0 付近で dy→dz / dx→dyaw になることは変わらない。R は当初から円筒 3D 同時残差のため、この雪崩は出ていない（pitch は −30° 前後を往復）。

U の LS を円筒 (z,θ) に移す方が効率的、という結論にはしていない。U の yaw は θ ではなく光軸ねじれで、自然な観測はフレーム座標のままである。

### 4.12 その他

- `cv2.remap` 幅 ≥32767 は NumPy フォールバック
- U 展開の黒筋は周期パッド
- GitHub 100 MB 制限のため `original_colormap/`（227 MB の png）はコミット対象外（`.gitignore`）
- 動画生成の全フレーム一括保持は逐次 `VideoWriter` に変更

### 4.13 U の yaw を自由変数にすると pitch が雪崩する

U `(-90,90,90)` で Mode A に dyaw を入れると、中心 ROI の x 流れが光軸捩れに載る。LS は過剰な yaw を dpitch で相殺し、全 320 フレームで U pitch が 90°→110° まで歩いた（hard bound ±25° 内）。`sigma_yaw` を 5°→0.4° にしても prior は 1 項、特徴残差は約 1600 点のため DC は止まらない。

yaw を Mode A から外して固定すると、同区間の U pitch は 90° 付近に留まる。接合ワープは (Δz, Δθ) の平行移動なので、R 展開に残る垂直基準線の湾曲（生成 `yaw_offset` による光軸捩れ）は吸収できない。捩れは誤差として残し、移動成分には入れない。

### 4.14 全行程キャンバス先確保による OOM

検証がオリジナルと同じフレーム数でも単一方向で落ちた。原因は全 z 範囲の color+filled 先確保と、毎フレームの全画面 ORB / scipy サンプリング。§3.9 の伸長キャンバスと ROI ORB に切り替え、全長 3 方向まで完走した。

### 4.15 巨大 `final.png` が先頭（0°）だけ見える

画素は埋まっているのにビューアが先頭数行だけ描く。自前 PNG の 1MiB IDAT と、フォトビューアのメモリ不足が重なる。§3.10 のとおり libpng 寄りのチャンクにし、縮小コピーも出す。RAM を空ければ全長 PNG も表示できる。

### 4.16 L 接合（180° 二重線と −60° の横ずれ）

3 面とも「両隣の 1/2 ワープ → 担当帯カット」だが、R/L の 180° が η=0 ラップ上にある。帯を周期にせず先頭行だけ見ると L の 180° 線（画像下端）を逃し、R と L の 180° 基準線が両方残る。−60° はキャンバス中ほどで帯は当たるが、`max_dz_mm=10` だと大きな横ずれを捨てる。接合帯を θ 周期にし、上限を 40 mm / 6° にした。
