| オプション | 正面 | 側視 |
| --- | --- | --- |

`python src/main_twopass.py` でも `import src.*` が通るよう、リポジトリルートを `sys.path` 先頭へ入れる。

## 8. 正面の移動量推定（物理 (θ, Z)、局所ロックと最終ワープ）

正面フレーム上の真マッチは放射状で、ベクトル長が Z 位置で変わる。長さ IQR もゾーニングも一様ベクトル前提なので誤マッチ検出に使えない。

円筒展開の行を物理管軸距離 `Z = R / tan(ζ)` にし、**両フレームを直前の使用姿勢で同じ管 (θ, Z) 地図へ載せる**。ORB は並進を見る。スクリーニングは ΔZ/Δθ の **DC+1 次を引いた残差** に IQR する（一様 Δθ を仮定しない）。

Δθ の発生源は roll だけではない。

- 0°/180° が大きく 90°/−90° が小さい → yaw
- その逆 → pitch
- 一様 → roll
- yaw/pitch は、θ が動かない方位では ΔZ（dz 側）を動かす

Δθ をすべて droll に積むと、yaw/pitch の 1 次がロールに漏れ、次フレームの条件を変えて雪崩する。円筒マッチングを false にしていた理由と同じ。マッチ 1 次を次フレーム展開へ積むと断層は減るが低周波がドリフトするので、Phase3 で戻す。

| 案 | 既知 | 推定 | 補正 | 判定 |
| --- | --- | --- | --- | --- |
| ① | x,y,yaw,pitch（平滑化 VP） | dz, droll | roll→0 | 1 次の残りが droll の DC に漏れる。減衰しても捩れ積分のリスク |
| ②（旧） | x,y,roll=0 | マッチからは dz。dyaw/dpitch は平滑化 VP | なし | VP 固定だと振動ブレの吸収変数が無い |
| ③ | x,y,yaw | dz, dpitch, droll | pitch→VP、roll→0 | 自由 roll が残る。pitch と roll の別名 |
| 局所ロック（採用） | x,y,roll=0。展開は前フレーム姿勢 | dz, Δyaw, Δpitch | Phase3: z→OCR、θ 低周波→VP | 断層はマッチ 1 次が吸収。蓄積ドリフトは最後に戻す |

### 8.1 採用契約

- 展開・マッチ・投影は直前フレームの使用姿勢（蓄積 yaw/pitch と生 z）を共通基準にする
- x = y = 0、roll = 0（Δθ の DC は積まない）
- dz とフレーム間 Δyaw/Δpitch はマッチ（点ゲートのあと DC+1 次残差 IQR、連立）
- 点ごとの `|ΔZ|≤20 mm`、`|Δθ|≤5°` は誤マッチ除去に使う。マッチ失敗対応で外すと IQR が誤った 1 次を残し、開始から蛇腹になる
- 後退 DC の全点捨てはしない（推定側で失敗）。スキップ連鎖の再発防止
- 消失点は Phase3 の低周波補正。フレームごとの VP 寄せ（`attitude_vp_blend`）は既定 0
- 画素 4/6DoF LS は正面主経路から外す
- Phase3: z は OCR、θ はマッチ蓄積姿勢の移動平均を消失点へ戻す（再マッチ・再展開しない）
- `estimation.max_abs_yaw_degrees`（既定 ±5°）は物理経路では掛けない。初期 VP が ~13° でもクリップしない

`apply_front_profile()` が `z_axis=physical`、空間/長さ/θセクターフィルタオフ、`estimate_droll=false` を正面だけ載せる。側視と ColorMapGenerator は触らない。

### 8.2 実装

| 段階 | 処理 | 場所 |
| --- | --- | --- |
| 展開 | 前フレーム `cam_pos/roll/yaw/pitch` で `world_to_pixel`。両フレーム同一 remap | `CylindricalFeatureMatcher._build_remap_maps` |
| マッチ | 連立 LS: ΔZ=−dz−kZ(dyaw cosθ + dpitch sinθ)、Δθ=(Z/R)(dpitch cosθ − dyaw sinθ)。droll=0 | `estimate_front_physical_option2` |
| 外れ値 | 点ごと `|ΔZ|≤20 mm`、`|Δθ|≤5°` のあと DC+1 次残差 IQR。後退 DC の全点捨てはしない | `filter_physical_motion_vectors` |
| 推定クリップ | 上限内なら採用。dz / Δyaw / Δpitch 超過は無効。低点数の 0.8°超・任意点数の 1.2°超の姿勢は 0（dz は積む） | `clip_front_physical_estimate` |
| 投影 | マッチ増分を積んだ `camera_state` をそのまま `add_frame` | `main_twopass._generate_colormap_frame` |
| 最終 z | OCR PCHIP（従来 Phase3） | `ColormapCorrector` |
| 最終 θ | マッチ姿勢の z 移動平均を VP へ。VP 欠測フレームは 0 埋めせず除外して補間 | `apply_front_attitude_trend_warp` |

設定（正面だけ効くもの）:

- `front.physical_z_matching`（既定 true）
- `correction.attitude_trend_enabled` / `attitude_window_mm=800` / `attitude_max_dtheta_deg=15` / `attitude_vp_blend=0`
- 円筒 `physical_max_dyaw_deg` / `physical_max_dpitch_deg`（フレーム間上限、既定 2°。超過は推定失敗）
- 円筒 `physical_max_dz_mm`（点の |ΔZ| と推定 dz の上限、既定 20 mm）
- `physical_max_dtheta_deg`（点の |Δθ| 上限、既定 5°）
- 円筒 `physical_min_points_for_attitude=20` / `physical_untrusted_attitude_deg=0.8` / `physical_max_applied_attitude_deg=1.2`。継ぎ目の 1.5° 級は積まない。微小振動は残す

既知 z 入力は CLI ではなく `z_source` / `known_z_metadata_path`。`--save-ocr-metadata` は出力専用。保存 JSON は `z_ocr_mm` と `ocr_z_mm` の両方を書き、読み側はどちらでも受け付ける。距離のみの JSON はレンズ校正を消さない。

### 8.3 特徴点数

`orb_max_features=3000` と `match_max_features=200` は上限であり、検出 2 桁・マッチ 1 桁の原因ではない。生フレームでは ORB が 3000 で頭打ちする。使う画素は `inner_radius_ratio=0.6`〜`outer_radius_ratio=0.83` の円環で、主点が右寄りだと展開の有効画素は約半分になる。管壁が平滑な区間では円筒上の検出が数十点、クロスチェックと物理 IQR のあと一桁になる。テクスチャがある区間は検出数百・マッチ 200 点超まで出る。

## 9. 展開後の帯重なり補正（絶対 z と roll）

3DoF マッチは `droll=0` のまま。継ぎ目の残り並進は、貼り位置ワープではなく **現フレームの絶対 (z, roll) を直して取り直す**。側視の ColorMapGenerator には載せない。

### 9.1 測定

魚眼上の既存マッチは使わない。展開後の既描画（画像1）と現帯（画像2）から ORB を取り直し、IQR と RANSAC で例外を除く。leftover は **帯 − 既描画**（`drow`, `dcol`）。

デバッグ PNG は補正前の画像2を重なりへ **100%** 重ね、矢印は既描画→帯、矢尻が帯側の特徴点。本番の貼り付け結果はここには出ない。

### 9.2 姿勢への戻し（符号）

実画像ではカメラ **+roll → 帯の行が +**（η 下向き）。帯が既描画より +η/+z なら、現在姿勢がその分進んでいるので **引く**。

| leftover | 意味 | 適用 |
| --- | --- | --- |
| `drow > 0` | 帯が +η | `ori[0] = roll0 − droll` |
| `dcol > 0` | 帯が +z（右） | `pos[2] = z0 − dz` |

`leftover_to_pose_delta` は進み量（正）を返す。`_try_abs_pose` が両方引く。roll の ± や z の逆向きは試さない。z+roll が RMS/ηビンで落ちたときだけ、同じ向きの z のみを再試行する。

ログの `dz=` / `droll=` は leftover ではなく、カメラに入れた増分。

### 9.3 採用判定

取り直し後に全体 RMS が下がること。η ビン（8 分割）のいずれかが 1 px 超悪化したら、z+roll は既定で破棄。理由は INFO の `reason=` に出す。

- `front.strip_overlap_allow_bin_worse=true` なら z+roll でもビン悪化を通す
- z のみはビン悪化を常に許容する（影響が小さい）

1 フレームのマップへの書き込みは `update_colormap` が一度だけ。補正が通れば取り直し後だけを書き、補正なし帯は残さない。マスクが古い η を覆わないと、前フレームの絵は残る。

### 9.4 設定（正面だけ）

| キー | 既定 | 意味 |
| --- | --- | --- |
| `front.strip_overlap_match` | false | 測定する |
| `front.strip_overlap_correct` | false | 測定した leftover で取り直す |
| `front.strip_overlap_allow_bin_worse` | false | z+roll でも η ビン悪化を通す |
| `front.residual_paste_warp` | true | 残差でサンプリングだけずらす。帯重なり測定時は無効 |
| `front.overlap_paste_align` | true | 貼り位置の位相合わせ。帯重なり測定時は無効 |

実験では residual / overlap_paste を切り、測定と絶対姿勢補正だけを見る。`data/config/default_config.json` の現地値はコミットしない。

実装: `src/front_strip_overlap.py`、`ColorMapGenerator._measure_and_maybe_correct_strip`。

## 10. Phase2 末尾の全体 roll 補正

帯ごとの roll 補正を積むと中盤で雪崩することがある。Phase2 の展開が終わったあと、蓄積 `roll(z)` で展開図の η を **roll=0 相当** へ戻す。Excel の roll 列は残す。再マッチしない。

### 10.1 ずらし方

入力はフレームごとのカメラ z と roll。補正は帯回数の階段ではなく、展開図を **1 回** `remap` する。各画素列のずらしは隣フレームの roll を直線補間（`np.interp`）。端の外側だけ最初/最後の値で平坦。

実測どおりカメラ +roll で行が + なので、列の移動は `d_rows = −roll(z) × H / 2π`。

帯を塗ったときはそのフレームの roll が帯幅で一定。戻すときはカメラ z の点の間を折線にする。

### 10.2 平滑化（比較用）

`front.deroll_smooth_roll`（既定 false）で、列へ直した roll を z 窓の移動平均してからずらす。窓は `front.deroll_smooth_window_mm`（既定 800 mm）。オフが折線のまま。同じ補正前画像に対してフラグだけ変えて比較する。

### 10.3 補正前画像

deroll の直前の展開図を temp の隣へ出す（`colormap_temp_{timestamp}_before_deroll.png`）。出し分けは Phase3 補正前と同じ `colormap.delete_temporary_images`。deroll 自体をスキップしたときは作らない。

### 10.4 長大図

OpenCV `remap` は一辺 32767 以上で失敗する。deroll は列同士を混ぜないので、幅を分割してずらす（`remap_column_eta_shift`）。姿勢トレンド θ ワープも同じ。

### 10.5 設定（正面だけ）

| キー | 既定 | 意味 |
| --- | --- | --- |
| `front.deroll_colormap_after_phase2` | false | Phase2 末尾に全体 deroll する |
| `front.deroll_smooth_roll` | false | ずらし量を z 方向に平滑化する |
| `front.deroll_smooth_window_mm` | 800 | 移動平均窓 [mm] |

実装: `deroll_colormap_to_zero`、`ColorMapPipelineTwoPass._deroll_colormap_after_phase2`。
